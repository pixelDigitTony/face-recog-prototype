# Physical camera and spoof-presentation evaluation workflow

Status: **Implemented and locally verified on 2026-11-05.** See the [parent acceptance audit](ANTHONYS_FACE_LAB_MOVEMENT_AND_PHYSICAL_EVALUATION_CHECKLIST.md). Frontend ReactJS/MUI/localStorage only. This implements a measurement tool; actual physical-camera performance and spoof resistance remain unmeasured.

## Scope and placement

Add Evaluation mode Physical camera and spoof trials beside existing all-sample and comparative modes. Preserve all existing recognition evaluation, Scan/Enroll gates, local records and model assets. Use real getUserMedia video with the same verified shared YuNet/MediaPipe adapters; do not create samples, people, attendance or identification history from evaluation. No seeded/fabricated measurements and no raw frames, embeddings, full landmarks or video in saved physical trials.

## Protocol

Before starting, require trial/session label, operator device label, lighting condition, appearance notes, expected visible group size1..10, target duration15/30/60seconds and an explicit acknowledgement that participants/presentations are authorized for local testing. Capture browser/camera resolution/settings where available. Labels can be pseudonyms; avoid requiring employee identity.

Start the measurement clock only after the camera/video is ready or the first fresh camera frame, excluding model initialization and permission wait. Initialization failures show an actionable setup error without starting a measured trial. Failures after the camera-ready boundary seal interrupted measurements. An empty scene still completes the timed protocol honestly without fabricated face results. A timed trial observes each visible face independently with the production meter and immutable prompted-challenge configuration. Challenges are test instructions in this mode only; keep Scan instruction-free. Require at least one prompted test for a combined-check trial. Meter pass and challenge pass remain separate metrics. Combined motion checks means both passed within the same continuously associated segment; it does not claim actual enrollment/identity acceptance, because enrollment pose/self-consistency and identification are separate workflows.

Track every face as a distinct segment with a stable segmentID, trackID, first/last seen times and camera-session binding. Missing or ambiguous tracking ends/invalidate that segment; reused numeric IDs cannot inherit proof. Later returned segments require new checks. Quality pauses retain accepted proof only while continuity remains. Independent people share bounded observation requests, not state. Cap in-memory segments100 and retain existing10-face configuration limit. End gracefully with a reason if limits/errors occur.

Each segment records valid fresh exclusive pose-observation count, observed span, mean sampling Hz/interval and maximum interval/gaps over200ms, time to meter pass, time to challenge pass, time to combined pass, peak transient movement score and accepted compact meter proof where present. Keep interval aggregation bounded; no raw time series persisted. Persist the verified detector/recognizer hashes and preprocessing/runtime identities, bounded Landmarker version/model/runtime-asset identities, meter and activity policy versions, and challenge snapshots and actual camera metadata so records can be interpreted later. Pinned local models are reused.

Automatically seal review at target duration. Stop early, camera disconnect, hiding, navigation and worker errors after measurement starts produce an explicit interrupted trial; incomplete no-pass is not counted as a rejection. Stop/retry/discard must cancel camera and both schedulers, fence stale async responses and retain any sealed pending save. Review rows default to Unscored. Operator assigns each selected segment a participant/presentation label and one of Genuine person, Attack presentation, Unscored. Attack rows require one subtype: stationary_print,moved_print,tilted_print,bent_print,display_photo,eye_mouth_cutout,prerecorded_video,camera_motion,other_presentation. Validate labels and truth at save; at least one scored segment is required. Background/unscored segments never enter result denominators. Explain segments are not independent participants and repeated/correlated trials are not an accuracy certification.

Save explicitly and atomically with exact retry/idempotent record IDs. Do not manufacture timestamps or re-run inference on retry. A failed write retains the exact sealed operation for retry/discard; editing is locked while an immutable save is pending. Existing data is preserved on quota/error. Allow deleting a saved physical trial explicitly and export JSON. Add a Physical trials tab and full View record dialog in Local database. Surface the separate 100-physical-trial cap without changing existing history/evaluation limits. Global reset/export include the new collection.

## Storage and reporting

Add optional schema5 `physicalTrials` collection (max100), absent in old DBs treated as empty without reinterpreting old records. Existing schema/key/settings capacities and overall3MB estimated-byte budget remain. Implement strict bounded validation for trial IDs/scope/timestamps/duration/completion reason, condition enums/lengths, truth/subtypes, model/policy identity, unique segments, finite metric/count bounds, pass ordering and compact proof/session binding. Recompute summary outcomes from recorded events rather than trusting arbitrary UI pass flags. New writes accept only physical-motion-evaluation-v1. No schema migration/reset or re-enrollment requirement.

Report completed timed scored segments separately from interrupted and unscored segments. Show actual denominators: genuine motion-check pass/non-completion, attack presentations passing motion checks, by attack subtype and optional lighting/device/group filters. Separate meter-only, challenge-only and combined results. Incomplete trials never become rejection evidence; show any observed passes from interrupted trials separately. Missing models/no observations stay incomplete/unmeasured. Show time-to-pass and cadence summaries only when observations exist; no0%/100% claims for empty denominators. Label rates Experimental motion-check results, not identity confidence or certified spoof detection. Explain physical cameras, lighting, glasses/makeup, facial mobility, groups1/2/4/10 and print/display/replay/camera-motion coverage as a checklist of planned versus observed trial conditions.

Record the end reason for each segment. A lost or ambiguous segment remains incomplete even when the overall trial later reaches its target duration. Exclude it from rejection/non-completion denominators and show any observed passes separately. Exclude segments without valid observations as unmeasured. Show short observation spans explicitly. Stale detector or pose responses interrupt measurement rather than converting an old partial observation into a completed negative result. A healthy detector observing an empty scene may still complete the timed protocol, with no fabricated segment outcomes.

## Architecture and verification

Runtime owner: new physical evaluation workflow, pure metric/report/record validator, optional repository collection/commits and unit tests. UI owner: MUI workspace/review/report components, camera hook/service injection, Evaluation mode and public contracts. Parent owns spec/UML/docs and all QA/browser tests. Reuse existing scheduler/exclusive association/meter/challenge functions; never run overlapping MediaPipe requests or compete with another active evaluation mode. Disable mode changes while active or pending sealed save, or guarantee teardown and retained review if navigation ends it.

Verify actual production reducers with finite fixtures, timed completion versus early interruption, no observations/missing worker, multi-face independence/reusedIDs, score/label isolation, honest empty denominators, per-subtype/filter reports, strict forged-record rejection, idempotent quota retry, historical optional-collection compatibility, no enrollment/identification writes, export/delete, camera teardown and desktop/mobile bounds. Unit/browser/format/build/UML required. Physical test measurements remain to be conducted by the operator; automated fixtures are not measured attack resistance.
